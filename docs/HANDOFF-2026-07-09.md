## IN PROGRESS — SSM migration (committed to branch `wip/ssm-deploy-config`)

**Goal:** remove the last PAT usage — Terraform's github provider in `terraform.yml`, which writes GitHub environment secrets. Replace with SSM Parameter Store so AWS OIDC is the only credential anywhere (user chose this over a GitHub App).

**Design decisions:**
- Terraform writes `cf-distribution-id`, `cognito-user-pool-id`, `cognito-client-id` to `/birdz/<env>/deploy/*` SSM params (new module `terraform/modules/deploy-config`).
- Deploy jobs fetch those via `aws ssm get-parameter` **after** `configure-aws-credentials` (step order must change: creds → fetch SSM → write config.json → sync → invalidate).
- `AWS_ROLE_ARN` stays a GitHub environment secret forever (OIDC bootstrap; chicken-and-egg — can't read SSM without it). Safe because the role name `birdz-<env>-github-deploy` is static, so the ARN never changes.
- Old GitHub secrets are **forgotten, not destroyed**: `removed` blocks with `lifecycle { destroy = false }` (destroying would need the dead PAT). Requires Terraform ≥ 1.7 (CI installs latest; fine).
- Keep `github` in `required_providers` until the forget-apply has run everywhere; drop it in a later cleanup commit.

**Done (committed on `wip/ssm-deploy-config`, pushed to origin):**
- `terraform/modules/deploy-config/main.tf` — new module (for_each over values map → SSM params)
